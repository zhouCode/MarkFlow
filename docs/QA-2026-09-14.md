# MarkFlow 测试记录 — 2026-09-14

本轮基于 `c9e2899` / package version `1.5.1`，在 Windows 上检查源码并测试真实 Electron 窗口。修复纳入 `1.5.2`，发布状态以 GitHub Release 为准。用户确认已解决的“进入编辑模式跳回开头”和“备注重叠”已在 TODO 中标记完成。

## 已复现并修复

| 问题 | 触发方式和原有表现 | 修复 |
| --- | --- | --- |
| Present 模式仍能修改文档 | Ctrl+B 可插入 `**bold**`；原实现只关闭直接输入，未限制命令修改，且会造成编辑器与 React 文档状态不一致 | 同时设置 CodeMirror readOnly、阻止自定义编辑命令、禁用编辑菜单与替换控件；搜索、复制和导航继续可用 |
| 格式快捷键冲突或缺失 | Ctrl+Alt+1/2 被标签切换抢占；Ctrl+I 被 CodeMirror 默认选区命令拦截；Ctrl+E 没有对应处理；带 Shift 的数字键按键值不可靠 | 应用快捷键在捕获阶段处理，区分 Alt 修饰键；补齐行内代码并按物理数字键识别列表快捷键；搜索框/地址框中的格式快捷键不改讲义 |
| 搜索面板控制不完整 | Present 下 Ctrl+F 不可靠；Ctrl+H 未展开替换；Escape 无法可靠关闭自定义搜索面板 | 明确处理打开、展开和关闭操作，增加关闭按钮 |
| 相对图片跨文件串用 | 两个目录都包含相同行号的 `![diagram](diagram.svg)`，切换文件后第二份文档仍显示第一份目录的图片 | 图片缓存键包含当前文档路径 |
| 网页焦点下应用快捷键失效 | 在内置网页输入框中，Ctrl+1、Ctrl+L、Ctrl+W 等未被主界面接收 | 在 Electron 网页输入钩子中转发限定的应用快捷键；网页缩放仍由网页自身维护 |
| 从文件启动时 IPC 未注册 | 带 Markdown 文件参数启动后，调用 `webTab:list` 报 No handler registered | 去除启动流程的提前返回，始终完成 IPC 注册与设置初始化 |
| 初始文档/备注状态可能丢失 | 窗口加载事件先于 React 的监听器注册，启动文档、重启恢复或首次打开备注会出现空内容 | 增加界面就绪握手，确保订阅完成后推送初始状态 |
| 撤销历史跨文档串用 | 从一份讲义切到另一份后 Ctrl+Z，可能撤销成旧内容或空白 | 每次打开文档创建新的编辑器实例与撤销历史；切换 Present 不重建编辑器 |
| 关闭窗口丢失未保存修改 | 编辑后直接关闭主窗口，没有确认提示，修改没有落盘 | 关闭、退出和安装更新前获取最新编辑缓冲，提供保存/放弃/取消；取消另存为、写入失败时保留窗口；保存通知携带实际已保存的快照，避免把后续输入误标为已保存 |

- `npm run typecheck` 通过。

回归用例覆盖：带文件参数启动、12 组 Present 格式快捷键、输入/删除/粘贴/撤销保护、编辑菜单、复制与查找、替换、标题与列表快捷键、格式切换、搜索框焦点、保存与磁盘内容一致性、相对图片切换、文档撤销隔离、备注打开/隐藏/双向滚动/关闭、长文档切换 Present 后的位置、网页 Node 隔离/缩放/切换/地址栏/关闭、PDF 导出、重启恢复和 renderer 异常。

追加 9 项用例：取消关闭、取消应用退出、取消安装更新、关闭前保存最后输入、放弃修改、无修改直接关闭、取消未命名文档另存为、保存失败保护、未命名文档保存后关闭。测试替换原生对话框的选择结果，实际执行窗口关闭、IPC 和文件读写；没有执行真实升级安装。

PDF 测试执行真实打印与文件写出，并在打印时检查正文包含讲义、不包含教师备注、本地图片已加载，确认输出为有效 PDF 文件头。没有逐页人工校验所有排版，也没有验证安装包自动升级。

网页测试使用本地 HTTP 页面，避免依赖 Remix 的联网状态；没有执行真实 Remix 编译、钱包连接或交易。原生网页快捷键通过 `WebContents.sendInputEvent` 验证，因为普通 CDP 键盘模拟绕过 Electron 的 `before-input-event`。

运行方式：

```sh
npm ci
npm run typecheck
npm run test:smoke
```

脚本：`scripts/electron-smoke.cjs`。使用系统临时目录中的讲义和独立用户配置，结果写入 `output/playwright/smoke-results.json`，截图写入同一目录；输出目录已被 Git 忽略。失败结果包含调用栈。运行测试需要桌面会话；当前用例按 Windows Ctrl 快捷键编写。

## 仍需处理或继续验证

1. **P1：系统/第二实例打开文件的保护仍需统一。** 主窗口关闭、应用退出和安装更新前的保护已修复。通过操作系统或另一个应用实例打开文件时，仍需要统一接入未保存确认流程。
2. **P2：开发启动脚本可能加载旧构建。** 代码检查发现 `npm run dev` 启动 Vite，但未设置 `VITE_DEV_SERVER_URL`；主进程仅在该变量存在时加载开发服务器，否则加载 `dist/renderer/index.html`。建议明确开发模式入口，并验证从干净目录启动及热更新。
3. **P2：长文档性能与模块拆分。** 构建提示 renderer 主 JS 约 1.52 MB（gzip 约 487 KB）；编辑器的装饰和图片定位在一些选区/滚动更新中扫描文档。150 节讲义的位置回归已通过，但未进行 CPU、内存或万行文档性能基准。建议按测量结果优化并拆分 EditView 的职责。
4. **跨平台与发布回归。** 尚未测试 macOS 交互、不同 DPI/多显示器下的窗口吸附、真实 Remix 操作、安装包安装和自动升级。44 项通过不代表这些场景已通过。

## 已有 GitHub Release 流程

来源：仓库 `.github/workflows/release.yml`、`package.json`，以及线上 v1.5.1 Release 与对应 Actions 记录。

1. `package.json` 和 `package-lock.json` 保持相同版本；完成检查后提交代码。
2. 推送 `v*` 格式的 Git 标签触发 Release workflow。普通代码推送只触发 CI。
3. `macos-latest`、`windows-latest` 分别执行 `npm ci`、类型检查、构建和 `electron-builder --publish never`；v1.5.2 起 Windows 打包前还须通过 Electron 回归测试。
4. Windows 步骤依据 `latest.yml` 校正安装包和 blockmap 文件名，避免更新元数据与实际附件名不一致。
5. 两个平台构建产物汇总后，发布 GitHub Release，自动生成发布说明，上传 `.zip`、`.exe`、`latest*.yml`、`.blockmap`。
6. 应用通过 `electron-updater` 读取 `zhouCode/MarkFlow` 的 GitHub Release。开发模式禁止检查/下载更新。

本轮发布前核实了 [v1.5.1](https://github.com/zhouCode/MarkFlow/releases/tag/v1.5.1)，发布日期 2026-05-13；[对应 Actions](https://github.com/zhouCode/MarkFlow/actions/runs/25806017195) 成功。附件包含 Windows x64 NSIS 安装包、macOS ARM64 zip，以及两平台的更新元数据与 blockmap。没有观察到 Intel macOS 安装包。

发布前应在 CI 验证修复、检查版本和标签一致性，并为用户编写有实际内容的变更说明。现有 workflow 在发布前会删除同标签的已有 Release；重跑相同标签时会短暂撤下旧附件，后续可改为更新现有 Release。本轮为发布 workflow 增加了类型检查和 Windows Electron 回归测试。
